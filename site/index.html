Transform SQL into a dbt Model

Devin takes raw SQL transformation logic and converts it into a clean, documented dbt model that maps to a data product contract — the core of migrating from legacy jobs.

Before: Raw SQL (jaffle_shop customers.sql)

with customers as (
    select * from {{ ref('stg_customers') }}
),
orders as (
    select * from {{ ref('stg_orders') }}
),
payments as (
    select * from {{ ref('stg_payments') }}
),
customer_orders as (
    select customer_id,
        min(order_date) as first_order,
        max(order_date) as most_recent_order,
        count(order_id) as number_of_orders
    from orders
    group by customer_id
),
customer_payments as (
    select orders.customer_id,
        sum(amount) as total_amount
    from payments
    left join orders on payments.order_id = orders.order_id
    group by orders.customer_id
),
final as (
    select customers.customer_id, customers.first_name, customers.last_name,
        customer_orders.first_order, customer_orders.most_recent_order,
        customer_orders.number_of_orders,
        customer_payments.total_amount as customer_lifetime_value
    from customers
    left join customer_orders on customers.customer_id = customer_orders.customer_id
    left join customer_payments on customers.customer_id = customer_payments.customer_id
)
select * from final

After: Clean dbt Model with Derived Fields

Devin rewrites the model with clear structure, self-documenting comments, and adds the customer_status field required by the Customer Profiles data product contract.

{{ config(materialized = 'table', tags = ['customer_profiles', 'data_product']) }}

-- Step 1: Pull base customer attributes from the staging layer.
with customers as (
    select customer_id, first_name, last_name
    from {{ ref('stg_customers') }}
),

-- Step 2: Aggregate order-level metrics per customer.
customer_orders as (
    select customer_id,
        min(order_date) as first_order_date,
        max(order_date) as most_recent_order_date,
        count(order_id) as number_of_orders
    from {{ ref('stg_orders') }}
    group by customer_id
),

-- Step 3: Aggregate payment totals per customer.
customer_payments as (
    select orders.customer_id,
        sum(payments.amount) as total_amount
    from {{ ref('stg_payments') }} as payments
    left join {{ ref('stg_orders') }} as orders
        on payments.order_id = orders.order_id
    group by orders.customer_id
),

-- Step 4: Join all CTEs and compute derived fields.
final as (
    select
        customers.customer_id,
        customers.first_name,
        customers.last_name,
        customer_orders.first_order_date,
        customer_orders.most_recent_order_date,
        customer_orders.number_of_orders,
        coalesce(customer_payments.total_amount, 0) as customer_lifetime_value,

        -- Derived: customer_status (required by Customer Profiles contract)
        case
            when customer_orders.customer_id is null then 'prospect'
            when customer_orders.number_of_orders = 1  then 'new'
            when most_recent_order_date >= dateadd('day', -90, current_date)
                then 'active'
            else 'lapsed'
        end as customer_status

    from customers
    left join customer_orders on customers.customer_id = customer_orders.customer_id
    left join customer_payments on customers.customer_id = customer_payments.customer_id
)
select * from final

Pipeline Triage

Devin investigates a broken dbt model, identifies the root cause, patches the test, and explains what it did — the kind of first-response triage that currently pulls engineers away from product work.

FIX 1 Autonomous Fix — Column Typo

CI Error: column 'custmer_id' does not exist

-- BROKEN:
SELECT customer_id, SUM(amount) AS total_revenue, COUNT(order_id) AS order_count
FROM {{ ref('orders') }}
GROUP BY custmer_id    ← typo: missing 'o'

-- FIXED (by Devin):
SELECT customer_id, SUM(amount) AS total_revenue, COUNT(order_id) AS order_count
FROM {{ ref('orders') }}
GROUP BY customer_id   ← corrected

Resolution: Autonomous fix — no business decision required. Devin spots the typo, explains why it fails, and produces the corrected model.

FIX 2 Escalation — Guest Checkout Handling

CI Error: not_null test failed for customer_id in orders model

Root Cause: The source table recently added rows where customer_id can be NULL for guest checkouts.

OptionApproachProsCons
AFilter out NULLsSimple, preserves testLoses guest order data
B (Recommended) COALESCE to sentinel (-1)Preserves all data, keeps testMagic number downstream
CSeparate guest modelCleanest designRequires downstream refactoring
-- RECOMMENDED FIX (Option B):
SELECT
    order_id,
    coalesce(customer_id, -1) AS customer_id,   -- guest sentinel
    order_date,
    status,
    amount,
    case when customer_id is null then true
         else false end as is_guest_checkout      -- downstream flag
FROM {{ ref('stg_orders') }}
Escalation Boundary: Devin recommends Option B but asks for engineer confirmation before applying. The choice of sentinel value (-1 vs. a dedicated 'guest' dimension key) is a business decision. This is what makes Devin safe to run autonomously — it knows when a fix requires a human decision and stops to ask.
